3 · Why gbrain MCP looked stalled (root cause)

It wasn't stalled — it was running the whole time.
  • opencode.json already registers mcp.gbrain → gbrain serve (enabled).
  • ps -p 43487: the server is alive right now and holds the PGLite single-writer lock.
  • Detection gap: gstack's setup-gbrain detect reads ~/.claude.json only, so it reports mcp_mode: none on OpenCode hosts. That false negative is what made it look unregistered.
  • Attachment gap: MCP tools attach at session start. Any session opened before registration sees no gbrain tools until restart.
  • Side effect worth knowing: while serve runs, CLI write commands are lock-blocked by design; sync delegates through the live server.
Unblock: restart an agent session → gbrain tools appear. Issue #4 closed with this evidence.
